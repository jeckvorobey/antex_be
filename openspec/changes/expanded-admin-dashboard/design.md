## Context

Admin dashboard должен за один запрос показать операционное состояние сервиса. `updatedAt` пользователя не является метрикой посещения: оно меняется при любых правках профиля. Поэтому активность требует отдельного поля, обновляемого только после успешной Telegram-аутентификации.

## Goals / Non-Goals

**Goals:**

- Сохранить совместимость старых потребителей `/api/admin/summary`.
- Считать календарный день в настроенной timezone проекта.
- Не смешивать суммы разных валют.
- Отдавать короткую, ограниченную очередь внимания.
- Возвращать курсы в человекочитаемой ориентации.

**Non-Goals:**

- Строить временные ряды и графики.
- Конвертировать обороты в единую валюту.
- Заменять отдельные CRUD endpoint заявок и курсов.

## Decisions

1. `lastActiveAt` nullable и индексируется. Исторические записи не объявляются активными без факта нового входа.
2. В очередь внимания попадают только незавершённые заявки: новые и находящиеся в работе. Новая заявка старше 30 минут и заявка в работе старше 4 часов помечаются просроченными.
3. Оборот считается SQL-агрегацией по обеим сторонам завершённой заявки и группируется по исходной валюте без пересчёта.
4. Старые `ordersToday`, `usersTotal`, `featuredRates` сохраняются; расширенные структуры добавляются рядом.
5. Полный `rates` включает все admin-пары, а совместимый `featuredRates` остаётся публичной тройкой.
6. Элементы `rates` и `featuredRates` возвращают `baseRate` и `baseRateDisplay` в той же display-ориентации, что и итоговый курс.
7. `baseRateDisplay` использует admin-точность пары, включая шесть знаков для внутренней обратной пары `RUBUSDT`.

## Risks / Trade-offs

- После миграции `activeToday` сначала будет ниже ожидаемого, пока пользователи не авторизуются повторно. Это честное поведение, а не искусственный backfill.
- Сводка выполняет несколько индексируемых aggregate-запросов. При существенном росте объёма можно добавить snapshot-таблицу, но сейчас это преждевременное усложнение.

## Migration Plan

1. Применить migration `028`.
2. Развернуть backend с расширенным совместимым контрактом.
3. Развернуть admin UI.
4. При rollback сначала вернуть UI, затем backend; migration допускает отдельный downgrade.
