## Why

Администратору нужно массово создавать реферальные коды только для пользователей, у которых `referral_code = null`, чтобы закрыть пробелы в данных без ручной обработки каждого пользователя. Сейчас эта операция должна быть явной, безопасной и предсказуемой для админки и backend-контракта.

## What Changes

- Добавляется/уточняется backend-поведение для массовой генерации реферальных кодов только для пользователей с `referral_code = null`.
- При генерации каждому подходящему пользователю назначается уникальный код, который сохраняется в БД.
- Backend предоставляет данные, необходимые admin-интерфейсу для отображения состояния и действия.
- **BREAKING**: отсутствующие коды больше не трактуются как “пустое состояние интерфейса” — для admin это явный сигнал, что можно предложить массовую генерацию.

## Capabilities

### New Capabilities
- `referral-code-bulk-generation`: массовая генерация реферальных кодов для пользователей с `null`-значением поля.

### Modified Capabilities
- `admin-referral-data`: уточняется контракт данных для админки, чтобы она могла показывать реферальный код, процент начислений и баланс вместе с состоянием доступности массовой генерации.
- `user-referral-profile`: уточняется выдача реферальных полей пользователя в backend-ответах.

## Impact

- Модель пользователя и связанные сервисы генерации referral_code.
- Admin API, которое инициирует массовую генерацию и получает данные для UI.
- Схемы ответа для таблицы пользователей и связанных реферальных экранов.
- Тесты на генерацию, уникальность кода и поведение при `null`-значениях.
